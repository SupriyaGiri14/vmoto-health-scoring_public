# Vmoto Health Scoring

Computes Vehicle Health Score and Battery Health Score for Engel's Vmoto
moped fleet, from raw ride-log telemetry, plus an interactive dashboard
to explore the results.

## Repository structure

```
vmoto-health-scoring/
├── app/                        <- THE DEPLOYABLE DASHBOARD (small, public-safe)
│   ├── dashboard.py             Streamlit app -- reads ONLY the small
│   │                            CSVs below, never touches raw log files
│   ├── data/                    Small, pre-aggregated CSVs (~350KB total)
│   │   ├── rides_summary.csv
│   │   ├── battery_timeseries.csv
│   │   └── vibration_timeseries.csv
│   └── requirements.txt         Minimal deps: streamlit, pandas, matplotlib
│
├── src/                         <- FULL RESEARCH PIPELINE (local only)
│   ├── load_logs.py              Reads raw files, handles 4 schema tiers
│   ├── battery_health.py         Battery Health Score
│   ├── vehicle_health.py         Vehicle Health Score
│   ├── vibration_pattern.py      Isolated vs persistent vs worsening
│   ├── overall_vehicle_health.py Multi-ride aggregation + trend
│   ├── device_vehicle_map.py     Device -> vehicle lookup
│   ├── export_dashboard_data.py  Turns raw files into the small app/data/ CSVs
│   ├── active_battery.py         Resolves which battery pack is genuinely active
│   ├── energy_efficiency.py      SOC-per-km (blocked, see caveats below)
│   ├── synthetic_labels.py       Placeholder curb/pothole/fall events
│   ├── summary.py                Combines all scorers into one result
│   └── visualize.py              Generates static PNG report charts
│
├── data/
│   ├── raw/                      GITIGNORED -- your actual Vmoto files, never committed
│   └── device_vehicle_map.csv    Device -> vehicle lookup table (small, committed)
│
├── tests/                        49 unit tests covering src/
├── charts/                       GITIGNORED -- generated by visualize.py
├── requirements.txt              Full dev dependencies (for src/ + tests/)
└── README.md
```

## Why two separate dependency trees

`src/` reads and processes the **raw** ride-log files, which are large
(hundreds of MB total) and should never be committed to git or published.
`src/export_dashboard_data.py` is the one bridge between the two worlds:
run it locally against your raw files, and it produces small, safe
CSVs in `app/data/`.

`app/` is deliberately self-contained and lightweight -- it only reads
those small CSVs, so it can be safely published (e.g. to Streamlit
Community Cloud) without ever exposing raw fleet data or needing the
432MB+ of source files.

## Running the dashboard locally

```bash
pip install -r app/requirements.txt
streamlit run app/dashboard.py
```

## Regenerating the dashboard data

Whenever new ride files are added to `data/raw/`:

```bash
pip install -r requirements.txt
python3 src/export_dashboard_data.py data/raw/ app/data/
```

Then commit the updated CSVs in `app/data/` and redeploy/refresh the app.

## Running the full test suite

```bash
python3 -m unittest discover tests
```

## Known caveats

- **Vibration threshold (2,900)** is calibrated on newer-logger-generation
  data only. Scores from older-logger devices are not yet directly
  comparable -- see `vehicle_health.py` for details.
- **Idle SOC threshold (1.2%/min)** is provisional -- only 6 real idle
  observations available so far.
- **Energy efficiency** (`energy_efficiency.py`) is blocked pending
  confirmation from the team on dual-battery draw behaviour (sequential
  vs. simultaneous).
- **Odometer / CAN fault flags** are not present in any ride-log file
  received so far, despite existing on the vehicle's CAN bus per the
  Vmoto CAN matrix documentation.
